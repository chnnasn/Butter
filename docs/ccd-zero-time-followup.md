# CCD 零时间重复碰撞：TomCat 原用例复测

## 来源与范围

本次在 `E:/Github/TomCat_Engine/.scratch/comparison-20260921` 找到了用户重测使用的 `compare.cpp`、`diagnostic.cpp` 和只增加只读统计接口的 `Physics2DDiagnostic.h`。适配器来自 `dev_butter`（`b44c9ec2305231793b4ea3fc4375446e7a540634`）。复制到 Butter 的 `build/tomcat-retest` 后使用当前 Butter 头文件编译；没有修改 TomCat 分支、子模块指针或 ekit。

原箱堆配置：10 列，间距 0.65，半边长 0.25，密度 1，摩擦 0.3，弹性 0；地板半尺寸 `(100,0.5)`，中心 `(0,-0.5)`；起点 `(i%10*0.65-16, 0.3+i/10*0.65)`。TomCat 用 Polygon fixture 表示盒子，根据密度计算质量与惯量，关闭线性/角阻尼。步长 1/60，8 次求解迭代，60 步预热加 300 步测量。此前 Builder 箱堆不能完全代替这条接入路径。

## 触发链与修复

1. 旧的零时刻判定要求角速度几乎为零。正在旋转、但当前接触点已经不再压入地面的箱体也会反复命中；每轮重做冲量仍不能满足该条件，最终达到四次重复保护。
2. 只查看当前法向速度或轨迹终点都不充分：另一角可能在稍后重新撞地。现在计算整个角运动区间的投影界，包含导数零点、双方相对平移及 fixture 偏移；超过一圈时使用常数成本的保守界。仅在现有 CCD 容差与浮点误差内确认整段安全时，才作为持续接触放行。
3. 会在稍后再次接触时，通过有上限的区间细化寻找经过检测的安全推进区间，确认下一状态接近实际接触后再求解。该路径也用于尝试恢复保守推进的未收敛候选；失败仍保留原来的局部保护。
4. 给区间搜索和持续接触判定留出不同的数值余量，避免浮点数恰好落在同一容差边界而永久重复命中。没有增大 `max_impacts=32` 或原有 CCD 几何容差。
5. 浅重叠超过 CCD 容差后，原 `sweep_shapes` 会交给离散求解。堆叠压力下，仅预求解并不能保证剩余运动安全。世界推进现在额外保护已有重叠，允许离开接触或沿接触运动，但不允许随后的运动继续加深穿透。单独的 `sweep_shapes` 查询契约不变。
6. 位置修正同样使用完整角区间检查，避免把安全的离地旋转误判成向内投影。
7. 原始圆形场景暴露了圆与长地面接触点的数值问题：从远端线段顶点重建最近点会丢失切向精度，产生微小倾斜法线并不断注入转矩。面内部改为从圆心做正交投影；端点接触保持原判定。增加 50 个原排列位置的法线与切向坐标回归。

诊断增加失败时的接触间距、法向速度及双方角速度；`persistent_contacts` 统计被完整轨迹检查排除的新撞击候选。原有三类失败原因及局部时间统计保留。

## 串行重复工作

- 同一次分离轴检测只生成一次双方顶点，支持点和接触特征复用这些顶点。
- 普通动态刚体之间本来就不启用 CCD，因此它们与静态环境的 CCD 时间线可独立求解。当前对不含 bullet/运动学物体、静态物体不超过 16 个的场景使用这条路径；否则保留耦合调度。共用静态地板不再导致每次局部撞击都重扫全世界。
- 独立路径保留碰撞对内的顺序并映射回原始诊断索引。不同独立刚体对之间不承诺全局 TOI 回调顺序；回调仍在世界锁内执行，不能通过回调修改其他刚体来建立隐藏的求解耦合。
- 没有引入多线程。静态环境较多、bullet 与运动学耦合的通用关联组调度仍是后续工作。

## 验证

Release CTest 16/16；最终 Debug 定向回归 3/3（CCD、原参数箱体、1,000 圆形）。`test_2d_ccd` 共 342 项检查，包括高速薄墙、旋转中途再次碰撞、局部偏移、浮点边界、已有重叠、独立/耦合时间线轨迹对比、扫描数量及诊断索引映射。

新 `test_2d_tomcat_stack` 固化原始接入参数，同时逐帧检查刚体底部不低于 -0.002、坐标有限、世界时间及独立运动探针，不能仅凭中心在地面之上或计时字段增加通过验收。

```powershell
build/tests/Release/test_2d_tomcat_stack.exe 100
build/tests/Release/test_2d_tomcat_stack.exe 500
build/tests/Release/test_2d_tomcat_stack.exe 1000
build/tests/Release/test_2d_tomcat_stack.exe 1000 circles
```

三个规模的 300 个测量步中，零时间重复、预算耗尽、未收敛与局部保护均为 0。100 箱体在 6 秒末全部休眠；500／1,000 箱体分别是 50／100 层高堆，6 秒末仍全部活动。不能把后两者描述为已经稳定休眠，或将不同活动状态的耗时解释为等质量求解器提速。

一次原生分阶段诊断中，1,000 箱体约为 CCD 0.82 ms、检测 9.71 ms、速度求解 1.74 ms、位置修正 38.75 ms／步（非适配层中位数）。主要剩余开销是位置修正与检测，后续应继续按此拆分验证。

圆形原始场景使用 50 列、半径 0.25、密度质量与圆盘惯量，其他参数同上；100／500／1,000 规模均正常推进并全部休眠，无 CCD 保护事件。

适配层 1,000 箱体连续运行六轮，去掉首轮，后五轮中位数 **52.147 ms／步**（范围 51.3461–72.0648 ms）。每轮均为 0 次 CCD 保护，末尾 1,000 个活动刚体。旧版存在局部冻结，且跨轮机器状态波动明显，因此不把它与用户旧报告的 239.352 ms 换算为等质量提速倍数；本次也没有重新测量 Box2D。原始输出保存在本机忽略目录 build/tomcat-retest/stack-1000-six-runs.txt。

同样六轮、去掉首轮的 1,000 圆形适配层中位数为 **5.92851 ms／步**，末尾全部休眠，每轮 CCD 保护计数为 0；输出在 build/tomcat-retest/circles-1000-six-runs.txt。

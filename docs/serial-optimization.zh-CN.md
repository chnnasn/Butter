# 2D 求解器串行优化

[English](serial-optimization.md)

本轮基于 `ea8ef90`，保持 CCD 次数预算、几何容差、休眠速度阈值和求解迭代次数不变，没有引入求解线程。
README 中的历史 TomCat 报告仍对应 `ea8ef90`，与本轮计时分开记录。

## 高堆为什么没有休眠？

将原始 1,000 箱体场景延长到 60 秒后，旧版在 15 秒前就已全部休眠。
5 秒时最大线速度约 13.2，10 秒时仍约 0.97；原来的 6 秒测试结束时，高堆仍在运动，不能通过放宽休眠阈值掩盖。
优化版也在 15 秒前全部休眠，并保持到 60 秒。长测试的独立时间探针改为每步沿 X 精确移动 1 个单位，避免累计浮点位置误差造成误报。

## 改动与失效规则

- 位置修正使用覆盖整段平移及旋转的包围盒查询缓存的静态/运动学障碍。
  旋转扩张量为 `radius * min(abs(angle), 2)`；远处障碍在 SAT 或保守推进前排除，近处候选仍执行原扫掠。
  障碍包围盒在积分后、位置求解前刷新。
- 2D 网格改为复用连续的单元和候选对缓冲，避免每次重建哈希容器与集合。
  候选对排序去重；刷新时检查包围盒和刚体类型，未变化时复用候选列表。
  速度求解不改变位置，因此事件阶段复用积分后的候选。
- 接触几何按检测时的精确变换、形状和 fixture 偏移快照复用；变换改变后重新检测，不近似复用旋转中的流形。
  摩擦与速度目标由当前输入更新。持续接触事件保留集合中的已有条目，避免逐步重新分配。
  关闭 CCD 时，近距离约束仍与实际接触事件区分。
- 每步开始检查公开变换、几何和偏移的修改，并重新检查过滤规则。
  销毁支撑 fixture、刚体或关节会唤醒相关关联组；外力或直接设置速度也会唤醒休眠刚体。
  销毁对象前清理接触引用。回调中的修改仍须延后到 `step()` 返回后。
- 刚体和接触/关节连接关系不变时复用关联组拓扑及缓冲。
  休眠组保留接触，但不进入每轮速度与位置求解；共用地板仍不会连接无关刚体，未提高休眠阈值。
- CCD 使用调用方持有的工作缓冲，并根据空间分布选择扫描轴，避免纵向稀疏场景枚举所有重叠的 X 区间。
  冲量改变轨迹后仍刷新扫掠范围。bullet/运动学耦合及独立静态环境的分组范围保持原有边界，未声称实现通用关联组 TOI 调度器。
- 多边形包围盒直接遍历本地顶点，不再分配世界顶点数组。

## 诊断与复现

`World::step_statistics()` 增加缓存维护、休眠/关联组耗时，以及活动约束、流形复用、位置修正/候选/扫掠次数、
活动刚体、仍在运动/等待休眠的组数、最大线速度、角速度、穿透和修正量。
休眠耗时包含唤醒传播；检测阶段不重复计入缓存维护。
`CcdStatistics::bounds_tests` 记录空间区间候选检查次数。世界统计包含诊断探针，不能把探针的活动组算作仍未稳定的箱堆。

```powershell
cmake --build build --config Release --parallel 4
ctest --test-dir build -C Release --output-on-failure
build/tests/Release/test_2d_tomcat_stack.exe 500 boxes 3600
build/tests/Release/test_2d_tomcat_stack.exe 1000 boxes 3600
build/tests/Release/test_2d_tomcat_stack.exe 1000 circles
build/benchmarks/Release/bench_2d.exe 1000 boxes
build/benchmarks/Release/bench_2d.exe 1000 boxes awake
```

最后一条基准每帧显式唤醒刚体，只与同样的强制活动负载比较。
两种模式均报告活动刚体步数与普通 C++ 分配次数；分配耗时已包含在阶段耗时内，不能重复相加。
TomCat 回归逐帧检查地板几何、真实探针运动、模拟时间和全部 CCD 失败计数；第四个参数为总帧数，包含 60 个预热步。

Release、Debug 的 CTest 均通过 17/17。
新增回归将修改与替换后的网格候选、触发器事件与暴力枚举对照，检查缓存失效、唤醒、离散事件语义，
并验证 200 个纵向分散 bullet 刚体的耦合 CCD 索引。原有薄墙、旋转再次撞击和低层箱堆长期静置测试同样通过。

## 计时边界

适配层来自 [TomCat `dev_butter`](https://github.com/chnnasn/TomCat_Engine/tree/dev_butter)。
独立测试目录分别接入 `ea8ef90` 和当前头文件，没有更新引擎分支及依赖指针。
旧、新二进制按轮交替顺序串行运行，六轮去首轮，60 步预热加 300 步测量，步长 1/60 秒，MSVC Release `/O2`，1,000 刚体。
编译和测试完成后再计时。本轮没有重新测量 Box2D，也不推算新的 Box2D 倍数。

末尾活动数量相同也不代表轨迹完全相同。表格比较相同初始场景的实际耗时，不保证每一步、每台机器都能满足 16.67 ms。
强制活动的分配测试单独提供显式匹配活动状态的负载。

## 结果

六轮交替运行、舍弃首轮后的中位数，单位为毫秒／步：

| 1,000 刚体场景 | 本轮实测 `ea8ef90` | 串行优化后 | 两版末尾活动刚体 |
| --- | ---: | ---: | ---: |
| 分散移动 | 1.350690 | 0.220543 | 1,000 |
| 圆形落地 | 6.888180 | 1.469910 | 0 |
| 箱体堆叠 | 55.151900 | 13.968000 | 1,000 |

箱体后五轮的范围为 13.848～14.0705 ms，当前负载的平均步耗时已低于 16.67 ms，但不保证每步峰值。
36 次计时运行均推进完整的 5 秒测量区间，CCD 限制、非有限坐标和地面内穿地中心计数均为 0。
箱体轨迹校验和有所不同（1881.63 与 1914.06），不能声称完全相同轨迹下的提速。
[六轮原始数据](benchmarks/serial-20260921.csv) 保留了被舍弃的首轮；`baseline` 为 `ea8ef90`，`retest` 为本轮串行优化版。

更严格的原生 500／1,000 箱体回归，在完整 3,600 步中逐帧检查底部几何，分别于 9.56667／12.1667 秒首次全部休眠，
保持到 60 秒。CCD 限制、未收敛、零时间重复和次数耗尽均为 0。结论限定于给定场景，不是任意几何或极端输入的正确性证明。

单独的 1,000 箱体原生分阶段诊断执行 300,000 个活动刚体步，总计 12.3505 ms／步：
CCD 0.7275、检测 4.9264、速度 1.7252、位置 4.1093、缓存维护 0.5225、休眠/关联组 0.3327 ms，其余为步进管理开销。
4,159,957 次接触点位置修正只产生 280,993 个障碍候选。
独立插桩的适配层测试中，过滤与接触事件回调约占 1.461 ms／步；该值已包含在物理步耗时内，且计时器本身有开销，不能重复相加。

# 2D 正确性修复与优化验收（2026-10-16）

本轮针对 `butter::physics2d`。历史多子步实验受到外力积分错误影响：每帧只施加了
`dt / substeps` 对应的重力、外力和力矩。现在每个子步积分一次，最后才清空累积器。
默认单子步保持原有受力语义；之前关于多子步、刚度和位置松弛的数字需要重新测量。

## 已交付的路径

| 方向 | 实现与边界 |
| --- | --- |
| 积分正确性 | 子步数为 1/2/4/8/16 时，整帧重力、力和力矩冲量一致；验证一秒运动和累积器只消费一次 |
| 稳定身份 | `BodyId` 的身份槽位与内部紧凑数组分离，包含世界标识；删除无关对象、槽位复用和移动世界均有回归 |
| 查询 | `query_batch` 一次同步服务整批查询；普通查询仍检查直接公共字段写入；最近射线命中可裁剪树的内部节点 |
| 关节过滤 | 每帧捕获公开开关，维护禁止碰撞的身份对索引；候选对不再遍历所有关节；开关变化使接触失效并唤醒相关组 |
| 岛与接触 | 精确比较求解拓扑，复用未变化的岛；接触缓存墓碑过多时同容量重哈希；轴对齐盒法向平移可选择复用接触锚点 |
| CCD | 复合形状候选在扫掠前使用覆盖整段平移、旋转和偏移的 fixture 包围盒证明分离；仍保留 TOI、预算和位置投影保护 |
| 求解数据 | 参与接触的刚体速度、角速度与逆质量集中到紧凑缓冲；关节交错求解使用原路径，以保证双方读取最新速度 |
| SIMD / 并行 | SSE2 一次计算四个独立单点接触岛，其他架构标量回退；主机可提供同步完成的岛任务调度器。均默认关闭 |
| 软接触实验 | `contact_hertz`、`contact_damping_ratio` 驱动质量无关的弹簧/阻尼系数及无偏置的积分后松弛；默认频率 0，保留刚性求解 |
| 测试 | Release 解除 `NDEBUG`；新增受力、句柄、批量查询、公开过滤修改、缓存、并行/SIMD 与标量对照、旋转扫掠包围盒回归 |
| 对照工具 | 同一场景定义接入 Butter 和固定版本 Box2D 2.4.1，输出编译配置、双方源码 SHA-256、耗时分位数和几何误差 |

这些改动没有消除所有全量扫描。兼容任意公共字段写入仍需要检查世界；批量查询
只把 Q 次扫描减为一次。岛复用也需要比较活动约束与关节拓扑，尚未成为完全增量的
图管理器。接触锚点复用只覆盖经过限制的盒接触，旋转、侧滑、特征变化和新接触仍
进行窄相位检测，不是完整的通用 TGS / Box2D Soft Step 替代实现。

## 使用方式

```cpp
world.query_batch([&](const auto& queries) {
    auto hit = queries.raycast({0, 10}, {0, -1}, 100);
    auto nearby = queries.query_aabb({{-1, -1}, {1, 1}});
});
```

批次内不能修改刚体、fixture 或世界；结构修改会抛出异常，直接公共字段写入仍由
调用方遵守只读契约。批次对象不能复制，也不能在回调返回后使用。

`Config::detailed_profiling` 默认关闭逐接触时钟，但阶段计时和操作计数仍保留。
`cache_solver_islands`、`buffered_velocities` 和 `ccd.tight_fixture_bounds` 可关闭以作对照。
`simd_contacts`、`translated_box_contacts` 默认关闭；`contact_hertz` 默认 0。

`Config::parallel_for(count, work)` 是可选的主机调度接口，必须对每个索引调用一次
`work(index)`，并在所有工作完成后才返回。它只调度互不共享可写刚体的接触岛；碰撞
查询、用户事件和关节仍串行。配置了交错关节求解时使用串行路径；同时启用 SIMD 和
任务调度器时优先执行 SIMD 路径。基准中的 `task_pool.h` 展示了一个持久线程调度器。

## 验证与旧测试修正

本地 MSVC 全量 CTest：Release **28/28 通过**（约 6.3 s），Debug **28/28 通过**（约 49.8 s）。两种配置均启用测试断言。

`test_2d_substeps` 现在包含独立于碰撞的解析受力测试。例如 `g=-12`、`dt=1/60`、
无阻尼时，1/2/4 个子步的速度都应为 `-0.2`，不是旧实现的 `-0.2/-0.1/-0.05`。

原 `test_2d_solver_options` 要求整个箱堆的最终误差随位置松弛系数严格单调。
修正完整重力后，系数 0.4/0.6 的误差分别约 18.93/19.15 mm，说明这一全局断言
不成立。现在用孤立接触的解析修正量验证局部线性关系，同时对所有箱堆参数分别
要求有限状态、原有地板穿透限制和 100 mm 顶高误差限制。没有提高 CCD 容差或休眠阈值。

修正后的既有 600 帧回归中，20 层箱柱顶高：8 次迭代、单子步约 14.529 m；双子步
约 19.480 m，接触高度为 19.5 m。50:1 质量比场景，4 次迭代、4 子步的顶端误差约
42.4 mm。它们是特定回归场景的数据，不是所有高堆和质量比均稳定的保证。

五个场景、12 种迭代/子步组合的完整 600 帧重测结果见[求解预算矩阵](benchmarks/optimization-20261016/solver-quality-corrected.txt)。其中时间列是整个 600 帧运行的总耗时，不能与下文的单帧 ms 直接比较。

已添加 Windows/Linux 的 Debug、Release 以及 Clang ASan/UBSan 工作流。远程 CI
需要推送后运行，本地结果与远程验证分开记录。

## 可复现基准

```powershell
cmake -S . -B build -DBUTTER_BUILD_EXAMPLES=OFF `
  -DBUTTER_BUILD_BENCHMARKS=ON -DBUTTER_COMPARE_BOX2D=ON
# 可额外指定 -DBUTTER_BOX2D_SOURCE_DIR=<Box2D-2.4.1源码目录>，避免下载。
cmake --build build --config Release --parallel 1
ctest --test-dir build -C Release --output-on-failure
./benchmarks/run_comparison.ps1 -Frames 300 -Count 1000
python benchmarks/summarize_comparison.py build/comparison
# 仅重测原求解器预算矩阵，跳过耗时更长的安排组合扫描：
build/benchmarks/Release/bench_2d_solver_quality.exe 600 --budgets-only
```

单次命令参数：`bench_2d_compare [场景|all] [帧数] [数量] [速度迭代] [子步] [awake|natural] [模式]`。
场景为 stack、mass_ratio、chain、fast、obstacles、queries、free、circles。每次运行
预热 60 帧、交替引擎先后顺序执行三轮。箱柱固定 20 层，质量比固定 10 个轻物体加
一个 50 倍重物体，关节链固定 24 节；数量参数用于障碍、子弹、查询、自由运动及圆形场景。

`baseline` 指**当前已修正积分的代码，关闭部分优化开关并启用详细计时**，不是旧版
Butter，也不是整个提交之前的二进制。因此下表只比较这组开关，不声称是整个提交的提速。

Box2D 保持默认 0.01 m 多边形皮肤；顶高偏差按用户定义的几何轮廓测量，包含皮肤间隙。
Butter 位置迭代与速度迭代相同，Box2D 位置迭代为 3；相同迭代数不能说明质量相等。
`quality_pass` 只是显式粗筛：地板穿透 ≤25 mm、高速薄墙穿透 ≤1 mm、关节间隙 ≤50 mm、
箱柱顶高偏差 ≤0.5 m。应继续结合原始误差选择预算，而不是把通过粗筛解释为质量相同。
独立运动探针检查实际时间推进；非有限状态或错误射线结果使程序失败。

`cpp_new_*` 统计普通 C++ 分配，不覆盖 aligned new、C malloc 或 Box2D 内部块分配器，
也不覆盖工作线程分配，不能据此声称两库内存性能相当。Box2D 不公开对应的 CCD 失败
计数，输出 `unavailable`。几何误差包含预热期间，时间统计只包含测量帧。

## 本机测量与采用决策

MSVC 19.50.35724.0，Release，步长 1/60，300 测量帧，数量参数 1,000；构建和测试
结束后串行计时。以下为三轮平均步耗时的中位数，单位 ms；不是跨硬件性能承诺。
原始 CSV 与完整源码指纹见 [数据目录](benchmarks/optimization-20261016/summary.csv)。

| 场景 | 关闭部分优化的 baseline | optimized | 说明 |
| --- | ---: | ---: | --- |
| 每帧 100 次射线查询 | 0.803541 | 0.023176 | 批量同步与内部剪枝；相同命中结果 |
| 1,000 高速物体 | 2.007053 | 1.805898 | 未发现穿墙，CCD 限制计数为 0 |
| 20 层箱柱 + 1,000 障碍 | 0.177770 | 0.166851 | 顶高偏差一致 |
| 1,000 个静置但强制唤醒的圆 | 2.088728 | 2.075458 | 差异很小，不作明显提速结论 |

独立圆形场景中，SIMD 模式约 1.827075 ms，相对 optimized 约减少 12%；四线程
调度模式约 2.593463 ms，反而更慢。它们均保留显式开关，不全局默认开启。

4 次迭代、4 子步的刚性求解中，质量比场景顶高误差约 64.25 mm，通过粗筛；
默认 8 次迭代、单子步约 9.89 m，未通过。软接触实验在同一 4×4 预算下，箱柱和
质量比误差分别约 1.24 m / 10.00 m，均未通过，所以频率默认仍为 0。单刚体载荷
测试通过不能代替高堆验收；这些负结果完整保留在 CSV 中。

本轮没有得出“Butter 全面追平 Box2D”的结论。下一步应以失败场景的质量—耗时
曲线推进求解器，而非默认启用更激进的软化、并行或放宽几何保护。

同批次 Box2D 2.4.1 的对照也显示剩余差距。例如强制唤醒、8 次速度迭代、单子步时，
高速场景 Butter / Box2D 分别约 1.806 / 0.919 ms，两者均未测到穿墙；24 节关节链
分别约 0.0330 / 0.00450 ms，最大锚点间隙约 8.66 / 10.40 mm。质量比场景中，
Butter 使用 4×4 预算约 0.1473 ms、顶高误差 64.25 mm；Box2D 使用 8×1 预算约
0.00854 ms、误差 32.68 mm。预算和误差都明确列出，不把它们换算成统一的引擎速度倍数。
